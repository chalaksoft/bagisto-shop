# MarketplaceServer — انتشار ماژول

سمت **فروشنده**. این ماژول روی نصبی می‌نشیند که مخزن است: ماژول‌ها را منتشر
می‌کند، بسته‌ها را با کلید خصوصی امضا می‌کند، لایسنس صادر می‌کند و API نصب را در
اختیار فروشگاه‌های مشتری می‌گذارد.

طرف مقابلش [`Marketplace`](../Marketplace/README.md) است که ماژول **نصب** می‌کند.
یک فروشگاه معمولی فقط آن را لازم دارد.

## راه‌اندازی

```bash
php artisan marketplace:keys
```

یک‌بار، روی همین نصب. کلید خصوصی در `storage/keys/repository.key` می‌ماند
(در `.gitignore` است) و کلید عمومی باید در ریپوی هر فروشگاه مشتری اینجا کپی شود:

```
Modules/Marketplace/resources/keys/repository.pub
```

⚠️ اگر کلید خصوصی لو برود، هر کسی می‌تواند بسته‌ای بسازد که همهٔ فروشگاه‌های
مشتری بی‌چون‌وچرا نصبش می‌کنند. اگر مجبور به تعویضش شدید، همهٔ نسخه‌های منتشرشده
باید دوباره منتشر شوند.

## گردش کار

۱. **ماژول → ماژول جدید** — نامک (شناسه در API) و نام پوشه (`Modules/{Name}` روی
فروشگاه مشتری، باید با نام پوشهٔ داخل zip و فیلد `name` در `module.json` یکی باشد).

۲. **آپلود نسخه** — شمارهٔ نسخه از `module.json` داخل خود بسته خوانده می‌شود، نه
از فرم. بسته با همان قواعدی بررسی می‌شود که فروشگاه مشتری موقع نصب اعمال می‌کند،
و بلافاصله امضا می‌شود.

۳. **صدور لایسنس** — مقید به دامنه. توکن خام فقط یک بار نشان داده می‌شود؛ در
دیتابیس هشش می‌نشیند. مشتری آن را در `.env` خودش می‌گذارد:

```
MARKETPLACE_URL=https://shop.example.com
MARKETPLACE_TOKEN=mkt_…
```

## اجزا

| فایل | کار |
| --- | --- |
| `Services/PackageSigner.php` | امضا و تأیید با کلید مخزن |
| `Services/VersionPublisher.php` | بررسی بسته، ذخیره، چکسام، امضا، انتشار |
| `Http/Controller/Api/*` | فهرست، جزئیات، دانلود، بررسی لایسنس |
| `Http/Middleware/ResolveLicense.php` | استخراج توکن و دامنه از هدرها |
| `Http/Controller/Admin/*` | پنل: ماژول‌ها، نسخه‌ها، لایسنس‌ها، دانلودها |
| `Console/Commands/*` | `marketplace:keys`، `publish`، `verify` |

اعتبارسنجی بسته پیاده‌سازی جدا ندارد: از `Modules\Marketplace\Services\Package`
استفاده می‌کند — همان کلاسی که خریدار موقع نصب به کار می‌برد. به همین دلیل
`requires: ["Marketplace"]` دارد.

## API

```
GET  /api/marketplace/modules?bagisto=2.3.7&php=8.3
GET  /api/marketplace/modules/{slug}
GET  /api/marketplace/modules/{slug}/download[?version=1.2.0]
POST /api/marketplace/license/check
```

`Authorization: Bearer {token}` و `X-Shop-Domain: example.com`.

فهرست بدون توکن هم جواب می‌دهد (فروشگاه باید ویترین را ببیند) ولی هر آیتم
`available` دارد که می‌گوید با لایسنس فعلی قابل دانلود هست یا نه. دانلود بدون
توکن فقط برای ماژول رایگان است.

پاسخ دانلود خودِ فایل zip است؛ چکسام و امضا در هدرهای `X-Package-Checksum` و
`X-Package-Signature` می‌آیند.

روت‌ها عمداً بیرون از گروه `web` ثبت می‌شوند: این یک API بدون وضعیت است و سشن و
کوکی و CSRF فقط سربار و سطح حمله اضافه می‌کنند.

## سلامت مخزن

```bash
php artisan marketplace:verify
```

بررسی می‌کند فایل هر نسخه هنوز با چکسام و امضای ذخیره‌شده‌اش می‌خواند. اگر فایلی
روی مخزن عوض شود — ریستور اشتباه، هارد خراب، نفوذ — فروشگاه مشتری با «امضای بسته
معتبر نیست» روبه‌رو می‌شود و ما تازه آن‌وقت می‌فهمیم. در cron بگذاریدش.

## جدول‌ها

پیشوند `marketplace_` دارند چون این نصب هم‌زمان یک فروشگاه بجیستوی معمولی است:

- `marketplace_modules` — ماژول‌های منتشرشده
- `marketplace_module_versions` — نسخه‌ها با چکسام و امضا
- `marketplace_licenses` — توکن‌ها؛ `customer_id` به جدول `customers` خود بجیستو
- `marketplace_download_logs` — دانلودهای موفق و ردشده

خریدار همان مشتری خود فروشگاه است؛ دفتر مشتریِ جداگانه یعنی دو جای نگهداری یک آدم.
